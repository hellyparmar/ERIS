# Testing and verification

## Suites

| Suite | Where | What it proves | Count (latest recorded) |
|---|---|---|---|
| API tests (SQLite) | `api/tests/` | Endpoints, roles, scope, imports, forecasting, assistant routing, caching, concurrency, isolation, security headers, rate limits, gates, TLS | 145 (confirmed by a full run on 2026-10-27) |
| API tests (PostgreSQL) | same, `api-postgres` CI job | Same, on PostgreSQL. Starts from an empty schema | 120 |
| End-to-end (Playwright) | `e2e/tests/` | The UI as a user sees it, per role, against a running API, under the Content-Security-Policy; session restore and renewal from the cookie | 15 |
| Assistant evaluation | `api/app/assistant_eval.py` | 31 intents routed correctly; 21 numbers match independent SQL | 31 + 21 |
| Forecast evaluation | `api/app/evaluation.py` | Rolling-origin back-test against the seasonal-naive baseline | 25 series |
| Anomaly evaluation | reported in the anomaly study (see `08`) | Precision and recall against labelled anomalies | 26 + 5 |
| Lint and build | `check.sh` and the CI `api` and `web` jobs | Ruff lint on the API; ESLint and a production build on the web app | — |

`check.sh` (repository root) runs the same checks as CI, in order: Ruff lint and API tests on SQLite; API tests on
PostgreSQL if `TEST_DATABASE_URL` is a PostgreSQL URL; web lint and build; the Playwright suite if `E2E=1`.

## Key tests (named by behaviour)
- `test_outlet_cap`: an eighth outlet is refused.
- `test_viewer_*`: viewers cannot write.
- `test_refresh_rotates…`: refresh tokens rotate and a reused token is refused.
- `test_audit_log_records_changes`: business changes are logged.
- `test_imports.py`: column mapping, dry run, atomic commit, errors.
- `test_isolation.py`: the pipelines stay separate (110 tests at the time, now part of the 120).
- `test_cache.py`, `test_concurrency.py`: cache and concurrent behaviour.
- E2E `expired access token…`, `viewer is read-only`, `area manager…`, `import with column mapping…`, `dashboard`, `forecasts`, `reorder`, `drivers`, `anomalies`.

## Fixes made because tests found real problems
- Hard-coded product IDs broke 18 tests. Fixed with SKU helpers in `conftest.py`.
- A 90-day demo broke the generator's revision range. Fixed with `min(75, days//2)`.
- The dish-search dropdown closed on quick refocus (stale blur timeout). Fixed with a ref and `clearTimeout`.
- A "this week" test failed on a Tuesday, when only one day of data exists. The correct baseline is the same day last week (d558b53).
- The rainfall driver returned NaN on PostgreSQL because rows were unordered (9653f22).
- A new page did not reset its scroll position. A Playwright test now fails without the fix (4b2ad6f).

## How to run

```bash
# API tests
cd api && pytest

# End-to-end (starts the API on a fresh SQLite database)
cd web && npm run build
cd ../e2e && npm test

# Screenshots for the README (needs a running demo)
cd api && uvicorn app.main:app --port 8000
cd e2e && node screenshots.mjs
```

On this host, Chromium is at `/opt/pw-browsers/chromium` and is used with `PW_CHROMIUM_PATH`.

## Verification rules
- Report exactly what was run. A failing run is reported as failing, with the output.
- Evaluation numbers are regenerated by scripts, not typed by hand (D18).
- A UI change is checked in the real app, not only in unit tests.
